# M1: real qwen35moe math, bit-exact against llama.cpp

M1 replaces M0's timing-only executor with the real decode math for `qwen35moe`
(Ornith-1.5-35B-A3B, Qwen3.6-35B-A3B) and an oracle harness that compares every
intermediate tensor against llama.cpp. **Gate: passed on Ornith with zero error.** Every
traced tensor in all 40 layers is bitwise identical to llama.cpp, at every position checked,
and so is every logit row.

## Which llama.cpp is the oracle (read this first)

| Reference domain | Build | What it computes |
|---|---|---|
| **native-layout oracle** (the M1/M2 gate) | `<llama.cpp checkout>` @ `ee6b9a1` (`claude/q3k-moe-gemm`), `GGML_CPU_REPACK=ON`, **`GGML_CPU_KLEIDIAI=OFF`**, same `-march` as production; `tools/oracle/build.sh` -> `$LLAMA/build-oracle` | the same kernels and layouts `oxe` vendors: Q3_K/Q4_K/Q5_K/Q6_K 8x8 and Q8_0 4x8 repack GEMVs |
| production (acd47/1bd builds) | same source lineage, **KleidiAI ON** | Q6_K (head, shared experts), Q8_0 and dense Q4_K are re-expanded to KleidiAI per-row int8: a *different* computation |

Matching the native-layout oracle bit for bit proves `oxe` computes exactly what llama.cpp
computes with these kernels. It does **not** prove numerical identity with the production
server. The production comparison is a KLD measurement (see M2.md), with Codex's
production-library oracle in the same file format.

### Compiler flags are part of the numerics

GCC contracts `a*b + c` into FMA by default (`-ffp-contract=fast` in GNU modes), and its
vectoriser decides how a loop is grouped. Bit-exactness therefore requires the same compiler
and flags as llama.cpp for every piece of scalar code. `kernels-sys/build.rs` builds:
- ggml-cpu items (repack kernels, arm quants, `vec.cpp`, the ported ops) with `-O3 -DNDEBUG -march=armv8.6-a+dotprod+i8mm+fp16+bf16+nosve+nosme`, the exact flags in llama.cpp's `build.ninja`;
- ggml-base items (`ggml-quants.c`: `quantize_row_q8_K_ref`, `dequantize_row_*`) with `-O3 -DNDEBUG` and **no** `-march`, as llama.cpp does.

(M0 used `-mcpu=oryon-1+...` for the kernels. They are now on the llama.cpp flags; see M2.md
for the speed re-run.)

## Schedule (changed from M0 for exactness)

| Phase | Per-thread work | Barrier |
|---|---|---|
| `deltanet_mix` | redundant RMSNorm + quantise. The thread's key heads, and value heads `kh + m*16` (llama.cpp maps value head v to key head `v % 16`, **not** `v / 2` as M0 assumed): q/k/v/z rows, beta/alpha row groups, conv + state, SiLU, l2norm, delta rule on its value heads' states (in place), gated RMSNorm | B |
| `deltanet_out` | quantise the 4096-wide mixer output, `ssm_out` own rows, `x1 = out + x` | B |
| `attn_qkv` | q (+gate) rows of own query heads, q-norm, RoPE; raw K rows (8-row split); V rows straight into the transposed f16 V cache | B |
| `attn_core` | K-norm + RoPE of the needed KV head (redundant, 256 floats; one designated thread writes the K-cache row), attention of own query heads, sigmoid gate | B |
| `attn_out` | as `deltanet_out` with `attn_output` | B |
| `moe_router` | post-norm, router rows (f32 `vec_dot_f32`), shared-expert gate (redundant), **shared expert gate/up rows -> h_shared slice** | B |
| `moe_gate_up` | routing (softmax, top-8, normalisation; redundant). Routed units = (expert slot, 256-row block): gate+up, swiglu, quantise the block. Shared-expert h blocks are quantised too. | B |
| `moe_down` | own output rows of all 8 experts' down projections (**full K = 512 per expert**) and the shared down, combined in llama.cpp's exact order: `((d0*w0 + d1*w1) + ... ) + dsh*g`, then `+ x1` | B |
| `head` | output norm, native Q6_K head GEMV, argmax (optionally full logits) | join |

**211 barriers/token** (30 x 5 + 10 x 6 + 1), up from M0's 171. The split-K MoE of M0
cannot be exact: llama.cpp's down GEMV accumulates both 256-blocks of K inside one kernel
call, and the per-expert partials are combined by a chain of `ggml_add`s in expert order.
The fix costs one extra barrier per layer (40 x ~0.7 us = ~0.03 ms/token at M0's measured
675 ns/barrier). In return, `moe_down` is perfectly balanced by rows, and the combine is
row-local. The down weights now use llama.cpp's ordinary per-expert row-group layout (no
transpose).

The plan is checked for exact coverage at 1, 2, 4, 6, 8 and 12 threads. On the tiny
synthetic model, and on the real model at 4, 6 and 8 threads, every logit is bit-identical
for any thread count.

## Results

Oracle: Ornith, prompt "The capital of France is" (5 tokens) + 16 greedy tokens, tensors
dumped at positions 0-3, 4 threads.

| Check | Result |
|---|---|
| tensors compared per position (40 layers: norms, qkv, conv, l2norm, gates, beta, GDN output, z, ssm_out, residuals, Q/K/V, q/k-norm, RoPE, kq softmax, attention, gate, router logits/probs/top-k/weights, MoE out, shared expert, ffn_out, l_out, result_norm, logits) | 923 |

boundaries, and two corpus chunks (M2.md).

## Divergences found and fixed

| # | Symptom | Localised by `oxe compare` to | Cause | Fix |
|---|---|---|---|---|
| 1 | pos 0 exact; pos >= 1: `conv_output_silu-0` 1 ulp off in 20-35 % of channels, growing to 1e-2 relative by layer 12 (expert top-k flips), logits off by ~1 | `ssm_conv` of layer 0 (all upstream ops exact) | My port compiled to an `fmadd` chain. llama.cpp's build of `sumf += s[i]*c[i]` is vectorised by GCC 16 into `fmul v.4s` + four **unfused** in-order `fadd`s (disassembled `ops.cpp.o` of the oracle). Position 0 hid it: the conv state is zero. | `oxe_ssm_conv_step_f32` now spells out the rounding (NEON multiply of 4, in-order adds, explicit `fmaf` tail), independent of compiler choices |
| 2 | (design, before any run) value head v reads key head `v % n_kheads` | source reading of `ggml_compute_forward_gated_delta_net_one_chunk` | M0's partition assumed `v / 2` | head partition: thread owns key heads K and value heads `{k + m*16}` |
| 3 | (design) split-K MoE not exact | see "Schedule" | — | full-K down per expert, llama.cpp add chain |
| 4 | (design) attention numerics | `build_attn_mha` + `ggml_compute_forward_mul_mat` | decode (n = 1) skips llamafile's tinyBLAS (`n < 2`): Q is rounded to f16, `ggml_vec_dot_f16`; softmax over the 256-padded `n_kv` with a -inf mask; probabilities rounded to f16; V^T dot. The SIMD/tail split depends on `n_kv`, so the padding rule `min(size, max(256, PAD(pos+1, 256)))` is reproduced | ported exactly (`oxe_attn_head_f16`) |

- kernels-sys: all five GEMVs vs ggml's generic and row-major references; op sanity.
- model: byte accounting vs `model_inspect.py` for both models; plan coverage and barrier
  count at 1-12 threads; first row group of each quant type of both real models (header +
  a few KB, skipped if absent). On a synthetic 4-layer GGUF (Q3_K/Q4_K/Q5_K/Q6_K/Q8_0): the
  weight cache is byte-exact vs the reference repack, warm hit, anon backing, corruption
  detected; decode is bit-identical at 1/2/3/4 threads, argmax is consistent and the
  barrier count matches.
